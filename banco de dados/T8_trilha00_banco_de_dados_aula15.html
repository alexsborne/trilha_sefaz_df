Resumo: conceitos básicos, ACID e papéis

O resumo segue a ordem da aula. Os termos em destaque são os que mais caem e os blocos vermelhos marcam as pegadinhas da banca.

1. O que é banco de dados

  • Definição genérica: coleção de dados relacionados. O uso comum é mais restrito e tem três propriedades implícitas:
#Propriedade
1Representa algum aspecto do mundo real (minimundo ou universo de discurso). Mudanças no minimundo refletem no banco.
2É uma coleção logicamente coerente de dados inter-relacionados, com significado inerente. Dados aleatórios não formam banco de dados.
3É projetado, construído e populado para uma finalidade específica, com grupo definido de usuários e aplicações.
  • Pode ter qualquer tamanho e complexidade: de uma lista telefônica ao banco da Receita Federal (cerca de 100 milhões de contribuintes).
  • Pode ser manual (fichário de papel) ou computadorizado.
  • Dados = fatos brutos registrados, com significado implícito. Informação = dados organizados e contextualizados que geram conhecimento. Exemplo: "82" é dado; "82 é a idade da Dona Neide" é informação.
  • Dados que registram eventos em tempo real ou mudam o tempo todo (vendas, transações financeiras) são dados transacionais.
Pegadinhas "Banco de dados é uma coleção de dados organizados de forma randômica, sem significado implícito": ERRADO.
O erro: negou a coerência lógica e o significado.
O certo: coleção logicamente coerente, com significado inerente.

"Banco de dados existe apenas em meio computadorizado": ERRADO.
O erro: restringiu o meio.
O certo: pode ser manual (um fichário) ou computadorizado.
Pergunte-se: uma pasta com 300 notas fiscais em papel, organizadas por contribuinte e data, é banco de dados?
Sim. É uma coleção logicamente coerente que representa um aspecto do mundo real, com finalidade específica. Só não é computadorizada.

2. SGBD, aplicações e sistema de banco de dados

  • SGBD: coleção de programas que permite criar e manter um banco de dados. Facilita: definição (tipos, estruturas e restrições), construção (armazenar em meio controlado), manipulação (consulta, atualização, relatórios), compartilhamento (acesso simultâneo), proteção (falhas e acesso não autorizado) e manutenção (evolução ao longo dos anos).
  • A definição do banco fica guardada no próprio banco, no catálogo ou dicionário de dados: são os metadados (dados sobre os dados).
  • Exemplos de SGBD: Oracle, SQL Server, DB2, MySQL, PostgreSQL, Firebird.
  • Aplicações fazem a ponte entre usuário e banco: traduzem cliques em comandos SQL. As operações básicas formam o CRUD: Create (inserir), Read (consultar), Update (atualizar), Delete (apagar).
  • SBD = BD + SGBD + [aplicações]. As aplicações não são obrigatórias.
  • O usuário não acessa os dados diretamente: passa pela aplicação, que fala com o SGBD, que lê os metadados e acessa o banco armazenado.
Pegadinhas "Banco de dados é o aplicativo que manipula dados inter-relacionados": ERRADO.
O erro: confundiu o banco com o software.
O certo: o banco é a coleção de dados; o software que o gerencia é o SGBD.

"Sistema de banco de dados é sinônimo de SGBD": ERRADO.
O erro: ignorou o próprio banco de dados.
O certo: SBD = banco de dados + SGBD (+ aplicações, opcionais).
Pergunte-se: na fase de "definir" o banco, o que se faz?
Especifica-se os tipos de dados, as estruturas e as restrições. Armazenar os dados já é "construir"; consultar e atualizar é "manipular".

3. Características da abordagem de banco de dados

Antes havia arquivos esparsos: cada setor com seus próprios arquivos, dados duplicados, inconsistência (o aluno corrige a idade num setor e esquece o outro) e falta de padronização (um setor chama o campo de TELEFONES, outro de CONTATOS).

Vantagens da abordagem de banco de dados (C. J. Date): dados compartilháveis, redução de redundância, minimização da inconsistência, melhoria na segurança, garantia de integridade, suporte a transações, padronização e conciliação de conflitos.

Característica (Elmasri e Navathe)Em uma frase
Natureza de autodescriçãoO banco guarda também os metadados (estrutura das tabelas, tipos, restrições) no catálogo.
Isolamento entre programas e dados, e abstraçãoProgramas não precisam saber como os dados estão armazenados; muda-se um lado sem quebrar o outro. Abstração = subtração de detalhes.
Suporte a múltiplas visõesCada usuário vê só o que precisa (visão, ou view).
Compartilhamento e processamento de transação multiusuárioVários usuários ao mesmo tempo, com controle de concorrência.
  • A eliminação primária da redundância ocorre no projeto, pela normalização; o SGBD força as restrições resultantes. Por isso a palavra é "reduzir", não "eliminar".
  • Deadlock (impasse): duas transações esperam indefinidamente uma pela outra; o SGBD desfaz uma delas.
Pegadinha"O suporte a recursos de análise de dados e aprendizado de máquina é característica que distingue a abordagem de banco de dados": ERRADO.
O erro: incluiu recurso adicional na lista clássica.
O certo: as quatro características são autodescrição, isolamento e abstração, múltiplas visões e compartilhamento multiusuário.
Pergunte-se: na SEFAZ, o servidor da área de logística deve ver as declarações de ICMS dos contribuintes? Qual característica resolve isso?
Não. O suporte a múltiplas visões: cria-se uma visão para cada perfil, e a logística não enxerga dados fiscais sigilosos.

4. Transações e propriedades ACID

  • Transação: unidade lógica de trabalho com uma ou mais operações de acesso e modificação, executada de forma a manter consistência e integridade. ACID não é exclusivo dos relacionais: aparece também em alguns NoSQL.
LetraPropriedadeIdeiaSubsistema responsável
AAtomicidadeTudo ou nada; se falhar no meio, desfaz tudo (rollback), usando o log.Controle de transações
CConsistênciaDe um estado válido para outro estado válido, respeitando as regras (chaves, domínios, regras de negócio).Controle de integridade
IIsolamentoTransações concorrentes não interferem; o resultado equivale a uma execução serial.Controle de concorrência
DDurabilidadeDepois do commit, o efeito persiste mesmo com queda de energia ou travamento.Recuperação
  • A atomicidade não garante sucesso: garante que não fique nada pela metade.
  • Consistência é parceria entre SGBD e projeto: quem define as regras é o projetista.
  • Isolamento evita leitura suja (ler o que pode ser desfeito), leitura não repetível (o dado muda entre duas leituras) e leitura fantasma (surge linha nova). Técnicas: bloqueios, controle otimista, MVCC. Mais isolamento custa mais desempenho.
  • Durabilidade usa log de transações (gravado antes da mudança), checkpoints, backups e replicação.
Pegadinhas "ACID: atomicidade, confidencialidade, isolamento e durabilidade": ERRADO.
O erro: trocou consistência por um princípio de segurança da informação.
O certo: C = Consistência (e A = Atomicidade, não autenticidade).

"A atomicidade garante que todas as operações sejam concluídas com sucesso, independentemente de falha": ERRADO.
O erro: confundiu tudo ou nada com sucesso garantido.
O certo: se houver falha, tudo é desfeito.

"A consistência garante que a instrução seja processada por completo, evitando perda de dados": ERRADO.
O erro: misturou atomicidade (por completo) e durabilidade (sem perda).
O certo: consistência = estado válido para estado válido.
Pergunte-se: duas transações concorrentes, isoladas, podem debitar o mesmo saldo e deixá-lo negativo?
Não. "Não interferir" não é "ignorar a outra": o resultado deve equivaler a uma execução em sequência. O isolamento não impede a concorrência; impede a inconsistência.

5. Principais papéis: DBA e AD

  • Papel (role): conjunto de permissões e privilégios. Em banco pessoal pequeno, uma pessoa só pode fazer tudo; com tamanho e compartilhamento, os papéis se separam.
  • DBA (Administrador de Banco de Dados): parte técnica. Instala, configura e mantém o SGBD; monitora desempenho; backup e recuperação; controle de acesso; índices; ajuste fino (tuning); atualizações; garante ACID. Atua no nível físico e também no lógico.
  • AD (Administrador de Dados): parte de negócio, conceitual. Modela entidades, atributos e relacionamentos; cria e mantém o dicionário de dados; define regras de negócio e padrões; cuida da qualidade; faz a ponte entre negócio e equipe técnica.
  • Resumo: o DBA cuida do como os dados funcionam; o AD, do porquê e para quê existem.
Pegadinha"Cabe ao DBA definir que o CPF deve ter 11 dígitos e ser único para cada cliente": ERRADO.
O erro: regra de negócio e padrão de dado são tarefa do AD.
O certo: o AD define a regra; o DBA a implementa no SGBD (por exemplo, criando a restrição e o índice).
Pergunte-se: a consulta de débitos de ICMS no sistema da SEFAZ ficou lenta na véspera do vencimento. Quem resolve?
O DBA: monitora a carga, cria índices e faz o ajuste fino das consultas.

ACID na prática: transferência de R$ 1.000

João (saldo R$ 2.000) transfere R$ 1.000 para Maria (saldo R$ 3.000). A banca costuma descrever uma propriedade e dar o nome de outra. Treine reconhecer cada uma pelo caso.

PropriedadeO que acontece no casoPalavra-gatilho na questão
AtomicidadeDebita João e credita Maria, ou nada. Se o crédito falhar, o débito é desfeito."tudo ou nada", "indivisível", "rollback", "não há transação parcial"
ConsistênciaAntes e depois, as regras valem: soma total R$ 5.000; saldos R$ 1.000 e R$ 4.000; nada negativo."estado válido para estado válido", "regras", "restrições de integridade"
IsolamentoSe outra pessoa paga uma conta da conta de Maria ao mesmo tempo, uma transação não lê dado não confirmado da outra."concorrentes", "simultâneas", "não interferem", "execução serial"
DurabilidadeConfirmada a transferência, o servidor cai: ao voltar, os saldos continuam R$ 1.000 e R$ 4.000."permanente", "persistente", "após o commit", "mesmo com falha"

Trocas que a banca faz

Pegadinhas de troca "Consistência garante que a transação seja processada por completo": ERRADO.
O erro: "por completo" é atomicidade.
O certo: consistência = estado válido para estado válido.

"Atomicidade garante que as alterações confirmadas sejam permanentes": ERRADO.
O erro: permanência é durabilidade.
O certo: atomicidade = tudo ou nada.

"O isolamento impede que transações sejam executadas ao mesmo tempo": ERRADO.
O erro: o isolamento não proíbe a concorrência.
O certo: permite a execução simultânea, desde que o resultado equivalha a uma execução serial.
Siglas intrusasConfidencialidade, autenticidade, integridade, disponibilidade, latência, concorrência e indexação não são letras do ACID. Se aparecerem no lugar de uma delas, o item está errado.
Problemas que o isolamento evitaLeitura suja: ler dado de transação ainda não confirmada. Leitura não repetível: o mesmo dado muda entre duas leituras da mesma transação. Leitura fantasma: nova linha aparece entre duas consultas iguais.
